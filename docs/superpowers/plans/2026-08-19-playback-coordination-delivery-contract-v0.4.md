# Playback Coordination, Secure Delivery, and Contract v0.4 — Implementation Plan

> **For agentic workers:** use `/implement` (TDD at the seams called out per task) to execute this plan task-by-task, checking off steps (`- [ ]` → `- [x]`) as they land. Run `npm test` and `npm run typecheck` at the end of every task, not just at the end of the whole pass. Nothing in this plan has been implemented yet — it specs the work described in `docs/superpowers/specs/2026-08-19-playback-coordination-delivery-contract-v0.4-design.md`.

**Goal:** Implement the full v0.4.0 breaking contract described by the design spec: `CorePlayer` becomes the sole owner of the canonical queue (queue-mutation commands replace direct `core.queue.*` access), `queueAuthority` is replaced by a `lookaheadPlayback` capability and a revisioned `PlaybackPlan` protocol, both web engines gain header-aware URL delivery through a new internal `@unitrack/media-delivery-web` module, `SourceToken`/`ResolvedSource` gain consistency validation and redaction rules, `checkSourceAvailability()` is replaced by an async `inspectSourceAvailability()`, `PluginRegistry.registerX()` gains stricter structural validation, and every package publishes its generated `.d.ts` through `package.json` `exports`.

**Architecture:** Six tasks, run in the dependency order the design spec's own "Migration and verification" section lays out — each task's types/behavior is a precondition for the next: contract types land first (Task 1), since every other task's JSDoc references them; the queue becomes Core-private next (Task 2), independent of the plan/delivery work but touching the same `CorePlayer.js` those tasks will also touch, so it goes first to avoid rebasing conflicts against itself; the plan-revision protocol and `engine-audio-queue` migration follow (Task 3), since it depends on Task 2's command surface existing (`#refreshLookaheadPlan` reacts to queue mutations); the web delivery helper is independent of Tasks 2–3 and lands next (Task 4); provider/resolver/conformance-kit/host redaction and token-consistency changes follow, since they depend on the final `SourceRef`/`ResolvedSource` shapes from Tasks 1–4 being settled (Task 5); registry validation, availability inspection, `.d.ts` exports, and the TypeScript consumer fixture close out the pass (Task 6), since strict registration validation must not fire false positives against any plugin migrated in earlier tasks. A final full-workspace verification (Task 7) closes the pass.

**Tech Stack:** Unchanged — plain JavaScript (ESM) with JSDoc types checked via `tsc --checkJs --strict`, tests via `node:test` + `node:assert/strict`, no new runtime dependencies (the web delivery helper uses native `fetch`/`Blob`/`URL.createObjectURL`, already available in both Electron's renderer and any browser target).

## Global Constraints

- `npm run typecheck` must report zero errors, and `npm test` must pass with pristine output, across every workspace package at the end of every task.
- `CONTRACT_VERSION` bumps to `'0.4.0'` in `packages/core/src/types.js`, independent of any individual package's own `package.json` version.
- Registration-time contract-version compatibility stays exact-match only (unchanged from v0.3.0) — this pass adds *more* validation at `registerX()`, not a looser version-matching policy.
- `token.token` and `ResolvedSource.headers` must never appear in a standard error payload, a user-facing event, or default logging anywhere they are touched in this pass (`Resolver.js`, `CorePlayer.js#emitError`, `inspectSourceAvailability()`, the conformance kit, `apps/electron-demo`'s `log()` calls).
- No mobile engine, no File System Access source, no producer of `ResolvedSource.kind: 'stream' | 'buffer'`, no public media-delivery plugin category, no third-party plugin loading/sandboxing — all explicitly out of scope per the design spec.

## Task 3: Revisioned playback-plan protocol + `engine-audio-queue` migration

**Files:**
- Modify: `packages/core/src/CorePlayer.js`, `packages/core/test/CorePlayer.test.js`, `packages/core/test/helpers/mockPlugins.js`
- Modify: `packages/plugins/web/engine-audio-queue/src/index.js`, `packages/plugins/web/engine-audio-queue/test/index.test.js`
- Modify: `packages/plugins/web/engine-web-audio/src/index.js` (capability declaration only)

**Interfaces:**
- `CorePlayer` gains a private, strictly-increasing `#planRevision` counter, incremented every time it installs, replaces, or invalidates a plan for the active engine.
- `#loadAndPlayCurrent()`'s branch on `engine.capabilities.queueAuthority === 'engine'` becomes a branch on `engine.capabilities.lookaheadPlayback === true`; the plan handed to `setPlaybackPlan()` is now `{ revision: this.#planRevision, entries }` instead of a bare array.
- `#bindEngine()` drops the `capabilities.queueAuthority === 'engine'` conditional `bind('trackChanged', ...)` and instead unconditionally binds `'playbackStarted'` and `'playbackExhausted'` for any `lookaheadPlayback` engine.
- `engine-audio-queue`'s `fire('trackChanged', { queueItemId })` call inside `handleActiveSlotEnded()` is replaced by `fire('playbackStarted', { queueItemId, planRevision })`; a new `fire('playbackExhausted', { queueItemId, planRevision })` call replaces the bare `fire('ended')` currently used when nothing is pre-buffered.
- `engine-web-audio`'s `capabilities` gains `lookaheadPlayback: false` in place of `queueAuthority: 'core'`.

- [ ] **Step 1: `CorePlayer.js` — plan revisions** — add `#planRevision = 0`; every call site that currently builds a plan via `#resolveLookaheadPlan()` (in `#loadAndPlayCurrent()` and `#refreshLookaheadPlan()`) increments `#planRevision` first and wraps the returned `entries` as `{ revision: this.#planRevision, entries }` before calling `engine.setPlaybackPlan()`.
- [ ] **Step 2: `CorePlayer.js` — accept-current-revision-only handlers** — replace `#reconcileEngineOwnedTrackChange(payload)` with two new private methods: `#handlePlaybackStarted({ queueItemId, planRevision })`, which is a no-op unless `planRevision === this.#planRevision` and `queueItemId` is present in the plan Core most recently sent, and otherwise updates `#loadedQueueItemId`/selection and emits Core's own `trackChanged` (as today); `#handlePlaybackExhausted({ queueItemId, planRevision })`, which is a no-op unless `planRevision === this.#planRevision`, and otherwise applies the same repeat/shuffle/end-of-queue resolution `#advanceOnEnded()` already implements (reuse that method directly). An event for an obsolete revision is silently ignored, not surfaced as an `'error'`.
- [ ] **Step 3: `CorePlayer.js` — non-fatal future-entry failure** — confirm `#resolveLookaheadPlan()`'s existing swallow-and-omit behavior for a lookahead entry that fails to resolve (`catch {}` around the per-item `resolveTrack()` call) still matches the spec's "current track continues, then the engine emits `playbackExhausted`" requirement; no change expected here beyond the revision-wrapping from Step 1, but add an explicit test (Step 6) since this behavior previously had no dedicated coverage.
- [ ] **Step 4: `#bindEngine()` — swap the conditional bind** — replace the `if (engine.capabilities.queueAuthority === 'engine') { bind('trackChanged', ...) }` block with an `if (engine.capabilities.lookaheadPlayback)` block binding both `'playbackStarted'` → `#handlePlaybackStarted` and `'playbackExhausted'` → `#handlePlaybackExhausted`, each still wrapped in the existing `#enqueue(...).catch(...)` error-forwarding pattern.
- [ ] **Step 5: `engine-audio-queue/src/index.js`** — `capabilities` becomes `{ gapless: true, backgroundPlayback: false, lookaheadPlayback: true }`; `setPlaybackPlan(plan)` now destructures `{ revision, entries }` and stores both (`#currentRevision`, `#entries` in place of the current bare `plan` variable); `handleActiveSlotEnded()`'s successful-handoff branch fires `'playbackStarted'` with `{ queueItemId, planRevision: <stored revision> }` instead of `'trackChanged'`; its no-pre-buffer branch fires `'playbackExhausted'` with `{ queueItemId: <the entry that just finished>, planRevision }` instead of the bare `'ended'`. A revision check at the top of `setPlaybackPlan()` should treat a lower-or-equal incoming revision as impossible (Core's counter is strictly increasing) but a defensive no-op guard is still reasonable groundwork for a future multi-engine scenario — document why rather than silently trusting the caller.
- [ ] **Step 6: `engine-audio-queue/test/index.test.js`** — migrate every `plan` literal to `{ revision, entries }`; add tests for a stale-revision `setPlaybackPlan()` call being superseded correctly (cancel outstanding prep, never start an entry from the old revision), for `playbackStarted`/`playbackExhausted` payload shape, and for the non-fatal future-entry-failure path (a lookahead entry whose resolve throws still lets the current track keep playing).
- [ ] **Step 7: `engine-web-audio/src/index.js`** — `capabilities` becomes `{ gapless: false, backgroundPlayback: false, lookaheadPlayback: false }`; its `on()`/`off()` event union already accepts `'trackChanged'`/`'transportCommand'` names defensively (see its existing comment) — update that comment's rationale to `'playbackStarted'`/`'playbackExhausted'` instead, since this engine still never fires either.
- [ ] **Step 8: `core/test/helpers/mockPlugins.js`** — `createMockPlaybackEngine`'s default `capabilities` drops `queueAuthority: 'core'` in favor of `lookaheadPlayback: false`; the `capabilities.queueAuthority === 'engine'` branch that conditionally adds `engine.setPlaybackPlan` becomes a `capabilities.lookaheadPlayback` branch, and the mock's `setPlaybackPlan` stores `{ revision, entries }` (exposing both via new `engine.plan`/`engine.planRevision` fields tests can assert against) instead of a bare array.

**Interfaces:**

- [ ] **Step 4: `engine-web-audio/src/index.js`** — `load(resolved)` calls `acquireWebMediaUrl(resolved, { signal: <a fresh AbortController's signal for this load> })`, assigns `audio.src = lease.url`, and stores `lease.release` in a module-scoped variable; a new `load()` call, `stop()`, and `dispose()` each release the previous lease (if any) before proceeding, and an in-flight `load()` superseded by a new one aborts its own fetch via the controller.
- [ ] **Step 5: `engine-audio-queue/src/index.js`** — `loadIntoSlot(slot, entry)` calls `acquireWebMediaUrl(entry.resolved, { signal })`, assigns `slot.el.src = lease.url`, and stores `lease.release` on the `Slot` object (new `Slot.releaseLease` field); every place a slot is reset or reused (`prepareNextSlot()`'s no-next-entry branch, `handleActiveSlotEnded()`'s inactive-slot reset, `stop()`, `dispose()`) releases that slot's lease first. - [ ] **Step 6:** Both engines' `package.json` gain `@unitrack/media-delivery-web` as a dependency (not `devDependency` — it's used at runtime, not just in tests); both engines' existing `test/index.test.js` suites gain at least one header-bearing `ResolvedSource` case exercising the new lease path end-to-end against the fake-fetch harness.
- [ ] **Step 7:** Run `@unitrack/media-delivery-web`, `@unitrack/engine-web-audio`, and `@unitrack/engine-audio-queue` test suites and typecheck.

**Files:**

- Modify: `packages/plugins/desktop/source-local-fs/src/index.js`, `packages/plugins/any/source-subsonic/src/index.js`, `packages/plugins/desktop/playlist-local-fs/src/index.js`, `packages/plugins/desktop/metadata-local-fs/src/index.js` (only where `ref.token.token` handling is affected by the new validation)

**Interfaces:**
- New `resolveTrack()` (or a thin wrapper Core calls before it) validates `ref.pluginId === ref.token.pluginId` for every `SourceRef` it's about to act on; a mismatch is rejected as invalid input *before* resolving, revalidating, or persisting the ref — surfaced the same way an unresolvable source already is (added to `failedSources` with a `reason` describing the mismatch, not a thrown exception that aborts the whole resolution attempt for other sources).
- `TrackResolutionError.failedSources`, `CorePlayer#emitError`'s `error` event payload, and any diagnostic logging touching a `SourceRef`/`SourceToken` continue to carry `pluginId`/`kind`/`displayPath`/a reason code, but never `token.token` or `ResolvedSource.headers`.
- Conformance-kit's `assertSourceProviderConformance()` gains an assertion that `sampleRef.pluginId === sampleRef.token.pluginId` (documents the invariant for every provider author who runs the kit) and that a deliberately-mismatched ref is rejected without the provider's `resolve()`/`revalidate()` ever being called.

## Deferred / explicitly out of scope (per the design spec)

- A mobile playback engine, a File System Access source provider, and any producer of `ResolvedSource.kind: 'stream' | 'buffer'` — the delivery-variant shape stays ready for them, nothing here builds them.
- A public media-delivery plugin category or a universal streaming abstraction — `@unitrack/media-delivery-web` stays internal to the two web engine packages.
- Third-party plugin loading, sandboxing, a marketplace, or any storage/persistence policy beyond what `CoreState` already covers (confirmed, again, as a host responsibility).
- Fully native background/gapless playback beyond what the browser/WebView JS thread allows — `engine-audio-queue`'s two-slot pre-buffering narrows, but does not close, the background-suspension gap documented in its own module comment; that remains true after this pass.
