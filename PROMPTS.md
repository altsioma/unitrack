## Prompt 8

Теперь можешь реализовать изменение `CorePlayer.prev()` из предыдущего анализа.

Обязательные условия:

1. Соблюдай `CLAUDE.md` и все связанные инструкции из `docs/ai/`.
2. Перед изменением ещё раз проверь актуальный diff и состояние репозитория.
3. Реализуй только описанное ниже. Не выполняй unrelated refactoring.

Зафиксированные решения:

* «Проигрывается больше 3 секунд» означает текущую позицию трека.
* Источник позиции — существующее `#position` в `CorePlayer`.
* Порог: `> 3` секунды. При `position === 3` выполняется обычный `prev()`.
* Если `position > 3` и есть активный engine в состоянии `playing` или `paused`, текущий трек перезапускается с позиции `0`, без перехода к предыдущему элементу.
* При перезапуске не нужно повторно разрешать текущий source, создавать новый playback plan или изменять очередь.
* После перезапуска воспроизведение должно продолжиться/начаться. То есть для `paused` сохраняем существующее поведение `prev()`: после операции воспроизведение запускается.
* Если состояние `idle` или `error`, новое правило не применяется: используется существующее поведение `prev()`.
* Первый элемент очереди при `position > 3` также должен перезапускаться.
* Shuffle/repeat не должны изменять свою текущую семантику. Перезапуск текущего трека не должен расходовать историю shuffle.
* Для перезапуска используй существующий механизм `seek(0)`, а не повторную загрузку трека.
* После перезапуска внутреннее `#position` должно быть сброшено в `0` корректным для текущей модели способом.
* Порог не должен становиться новой пользовательской настройкой или частью публичного API.

Тесты:

Добавь regression tests в `packages/core/test/CorePlayer.test.js`, покрывающие как минимум:

* position > 3 → текущий трек перезапускается;
* position === 3 → выполняется обычный `prev()`;
* position < 3 → выполняется обычный `prev()`;
* первый элемент + position > 3 → текущий трек перезапускается;
* два последовательных `prev()`: первый перезапускает текущий трек, второй при position 0 переходит к предыдущему;
* paused + position > 3 → после операции воспроизведение запускается;
* shuffle → перезапуск не расходует историю;
* idle/error → сохраняется существующее поведение.

Не ослабляй и не удаляй существующие тесты.

После реализации выполни проверки в соответствии с `DEVELOPMENT.md` и `VERIFICATION.md`. Минимально:

1. `npm test -w @unitrack/core`
2. `npm test`
3. `npm run build:types`
4. `npm run typecheck`

Если какая-либо проверка не может быть выполнена или падает, не называй её пройденной — укажи фактический результат и причину.

* проверь архитектурные границы;
* проверь тесты;
* проверь отсутствие unrelated changes;
* проверь документацию и публичные контракты.

Не создавай design spec для этой задачи: решение о необходимости спецификации уже принято — для данного изменения она не требуется.

В финальном ответе строго используй формат из `CLAUDE.md`:

В `Changes` перечисли конкретные изменённые файлы и существенные изменения.
